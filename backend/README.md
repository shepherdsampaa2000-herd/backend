# TechBridge – ICT251 Activity 7 Backend

This is the independent Node.js API for the TechBridge IT Support Desk System created in Activity 6.

The Activity 6 frontend uses these same record fields:
- `id`
- `title`
- `category`
- `description`
- `status`

The sample data below is carried over from the Activity 6 frontend, including its eight demonstration support tickets.

## Technology
- Node.js and npm
- Express
- PostgreSQL through the `pg` package
- Postman for API testing

## Set up
1. Open a terminal in this folder.
2. Run `npm install`.
3. Create a PostgreSQL database.
4. Run `schema.sql` in that database to create the `records` table.
5. Run `seed.sql` once to insert the eight sample tickets.
6. Copy `.env.example` to `.env` and enter your database connection string.
7. Run `npm start`.
8. Open `http://localhost:3000`.

If PowerShell blocks npm, use `npm.cmd` instead of `npm`.

## Required routes

| Method | Route | Purpose |
|---|---|---|
| GET | `/` | API guide for the marker |
| GET | `/health` | Check server and database |
| GET | `/api/records` | Read all support tickets |
| GET | `/api/records/:id` | Read one support ticket |
| POST | `/api/records` | Create a support ticket |
| PUT | `/api/records/:id` | Update all editable fields |
| DELETE | `/api/records/:id` | Delete a support ticket |

## Shared data agreement
- `id`: positive whole number generated by the database; do not send it.
- `title`: 3–80 characters.
- `category`: 2–40 characters.
- `description`: 5–300 characters.
- `status`: exactly `Pending`, `In progress`, or `Completed`.

Example POST/PUT JSON body:

```json
{
  "title": "Wi-Fi Disconnects in Study Hall",
  "category": "Network",
  "description": "The wireless network disconnects repeatedly in the main study hall.",
  "status": "Pending"
}
```

POST and PUT require all four editable fields. PUT replaces all four fields and does not create a missing ticket. Any client-supplied `id` is ignored.

## Test using Postman
For POST and PUT choose **Body → raw → JSON**.

1. `GET http://localhost:3000/health` – expect 200.
2. `GET http://localhost:3000/api/records` – expect 200 and a JSON array.
3. `POST http://localhost:3000/api/records` with the example body – expect 201. Save its returned `id`.
4. `GET http://localhost:3000/api/records/ID` – expect 200 and that ticket.
5. `PUT http://localhost:3000/api/records/ID` with all four editable fields – expect 200 and the same id.
6. `DELETE http://localhost:3000/api/records/ID` – expect 200 and `{"message":"Record deleted."}`.
7. Try missing fields, invalid lengths, an unknown status and malformed JSON – expect 400.
8. Try a positive id that does not exist – GET, PUT and DELETE should return 404.
9. Restart the server and retrieve an existing ticket to confirm the database retains records.

## Hosting
1. Push this backend folder to GitHub. Include `package.json` and `package-lock.json`; exclude `.env` and `node_modules`.
2. Create a PostgreSQL database and a Render Web Service connected to the repository.
3. Set the backend folder as the root directory if it is inside a larger repository.
4. Build command: `npm install`
5. Start command: `npm start`
6. Add `DATABASE_URL` in the host's environment settings. Set `DATABASE_SSL=true` if required by the database provider.
7. Deploy, open the assigned HTTPS URL, check `/health`, then repeat all CRUD tests using the hosted URL.

Before submission, replace the student name and student number placeholders in the HTML guide inside `server.js`. Submit the live backend base URL as required by Activity 7.
